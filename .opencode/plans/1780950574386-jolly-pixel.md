# Argus Property Intelligence Revamp Plan

## Goal

Revamp Argus into a fully Dockerized, Postgres-backed property intelligence system that avoids duplicate AI spend through address-first caching, removes Supabase, adds field-level provenance, integrates Langfuse Cloud observability, and prepares for local SAM 3.1 segmentation.

## Key Decision From The Provided Prompt

Use the Canadian residential property prompt to shape the extraction contract and evidence model before building the database, but do not create one database column for every prompt field.

The important pieces to preserve are:

- Canadian/Ontario residential conventions where applicable.
- A reasoning hierarchy: exact listing data, historical listings, same-street comparables, subdivision/builder patterns, imagery, then regional conventions.
- Probabilistic inference instead of simply omitting uncertain values.
- Field-level confidence.
- Field-level basis/explanation.
- Distinction between observed, inferred, assumed, and unknown.
- Source tracking per field.
- A complete raw model output retained for audit/reprocessing.

Store stable identity and artifacts relationally. Store evolving intelligence as normalized observations with JSON values and source/provenance links.

## Recommended Architecture

Services:

- `backend`: FastAPI app.
- `frontend`: existing React/Vite-plus app.
- `postgres`: primary persistent database.
- `pgadmin`: optional local DB UI.
- `sam`: local SAM 3.1 segmentation service, called over HTTP by backend.

External services:

- OpenAI for analysis/reasoning, model names configurable by env.
- Langfuse Cloud via env-provided credentials.
- Hugging Face gated checkpoint access for `facebook/sam3.1`.

Local secret handling:

- Prefer `s env` for `OPENAI_API_KEY`, `HF_TOKEN`, `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, and `LANGFUSE_BASE_URL`.
- Keep `.env.example` documentation-only with no real values.

## Cache Flow

Primary identity is address-first.

1. Receive `lat/lon` property request.
2. Reverse geocode to obtain address/components.
3. Normalize address into a canonical form and hash.
4. Look up `properties` by address hash / normalized address.
5. If no address match, optionally fallback to coordinate proximity with low confidence.
6. If a fresh profile exists under TTL, return cached DB result without OpenAI or SAM calls.
7. If missing or stale, create a search record and refresh data sources.
8. Fetch street view, satellite, POIs/geospatial context.
9. Call SAM service if configured/available.
10. Run segmented reasoning with configurable OpenAI model.
11. Validate parsed output, persist profile snapshot, observations, sources, and raw extraction run.
12. Return current frontend-compatible response while preserving richer data internally.

Use TTL by data/source type rather than one global value:

- Geocode/address: long TTL.
- Imagery URLs/assets: medium TTL.
- Geospatial/POI snapshots: medium TTL.
- AI profile: configurable TTL, initially `PROPERTY_CACHE_TTL_DAYS`.
- Extraction rerun should also consider source/input hash changes.

## Extraction Contract

Create a Pydantic model for the new model output before writing DB rows.

The LLM should output:

- Address and location fields.
- The current Argus UI fields for compatibility.
- The richer Canadian property fields from the provided prompt.
- `data_quality_note`.
- `sources_used`.
- Per-field confidence and basis for all inferred/uncertain values.
- Observed-vs-inferred status.

Prefer a canonical field wrapper for new fields:

```json
{
  "value": "...",
  "confidence": 0.72,
  "confidence_label": "medium",
  "evidence_kind": "inferred",
  "basis": "Street view shows...",
  "sources_used": ["street_view", "satellite", "regional_convention"]
}
```

Keep a compatibility mapper that converts the observation model back into the existing frontend `analysis` shape until the frontend is redesigned.

## SAM 3.1 Plan

Use `facebook/sam3.1` checkpoints and latest `facebookresearch/sam3` code.

Constraints:

- Python 3.12+.
- PyTorch 2.7+; guide uses `torch==2.10.0` with CUDA 12.8 wheels.
- CUDA-compatible GPU with CUDA 12.6+.
- Gated HF checkpoint access.
- Auth through `HF_TOKEN`, ideally via `s env`.

SAM service behavior:

- Expose HTTP endpoint used by backend.
- Load SAM model at service startup, not per request.
- Accept image URL and target prompts.
- Return masks, overlays, boxes, scores, and raw response.
- If unavailable, backend records segmentation unavailable and continues.

Initial target prompts:

- Home boundary: `the residential home directly under the map marker, including the full visible building footprint`.
- Pool: `the swimming pool on the same residential property as the map marker`.
- Driveway: `the driveway belonging to the residential home directly under the map marker`.
- Roof: `the roof of the residential home directly under the map marker`.
- Garage: `the garage door or garage structure of the home in focus only`.

## Langfuse Plan

Use external Langfuse Cloud, not Dockerized Langfuse.

Before implementation, fetch current Langfuse docs and follow current SDK guidance.

Trace:

- Property request/session.
- Cache lookup result: hit, miss, stale.
- Address normalization/geocoding.
- Image fetches.
- SAM segmentation calls.
- OpenAI calls.
- Prompt names and versions.
- Validation failures.
- DB persistence steps.
- Token usage and cost metadata where available.

Persist Langfuse IDs in `property_searches`, `property_profiles`, `ai_extraction_runs`, and `model_usage_events`.

## Implementation Phases

### Phase 1: DB And Supabase Removal Foundation

- Add Postgres and pgAdmin to Docker Compose.
- Add `DATABASE_URL` and Postgres settings.
- Add DB dependency and migrations.
- Remove Supabase config/dependency/service usage.
- Create initial tables for properties, searches, profiles, sources, imagery, observations, extraction runs, usage events, geospatial snapshots, and feedback.
- Preserve graceful degradation where possible.

### Phase 2: Cache-First Property Flow

- Implement address normalization and address-first lookup.
- Add cache hit/miss/stale orchestration.
- Add TTL config.
- Persist search and profile records.
- Return cached profile without OpenAI/SAM calls when fresh.
- Keep current API response shape through a compatibility mapper.

### Phase 3: Rich Extraction Contract

- Convert the provided Canadian prompt into a versioned prompt contract.
- Add Pydantic validation for model output.
- Store stable fields as observations with confidence, basis, evidence kind, and sources.
- Preserve raw output in `ai_extraction_runs`.
- Keep existing frontend fields populated from observations.

### Phase 4: Langfuse Integration

- Update tracing to sessions and spans for the full pipeline.
- Add prompt names/versions and model usage tracking.
- Store Langfuse trace/observation IDs in DB.
- Ensure secret masking remains active.
- Document `s env` usage.

### Phase 5: SAM Service Interface

- Add backend SAM client and service contract.
- Store segmentation runs/outputs.
- Gracefully continue if SAM service is unavailable.
- Feed segmentation outputs into the analysis input when present.

### Phase 6: SAM 3.1 Local Service

- Add `sam-service/` image using latest `facebookresearch/sam3` code.
- Use `hf download facebook/sam3.1` or equivalent authenticated checkpoint retrieval.
- Cache HF model files in a Docker volume.
- Require GPU/CUDA for full service operation.
- Add health endpoint and startup validation.

### Phase 7: Frontend Provenance UI

- Add optional display of confidence, basis, and observed/inferred labels.
- Expand feedback to target observation IDs where available.
- Avoid blocking backend rollout on this UI work.

## What Not To Do

- Do not create one typed column for every field in the provided prompt.
- Do not hardcode Ontario-only logic into core schema.
- Do not make SAM required for basic property search.
- Do not fail app startup when OpenAI, Langfuse, HF, or SAM are unavailable.
- Do not store secrets in `.env.example`, committed files, logs, or Langfuse traces.
- Do not lose raw AI outputs; keep them versioned and auditable.

## Verification Plan

Backend tests:

- Cache miss creates property/search/profile/observations.
- Cache hit returns stored profile and does not call OpenAI/SAM.
- Stale profile refreshes and creates a new profile/extraction run.
- Address alias lookup maps repeated searches to the same property.
- DB write failures return clear errors without crashing the whole request when graceful degradation applies.
- SAM unavailable path returns profile with segmentation-unavailable metadata.
- Extraction validation failures are stored and surfaced safely.
- Feedback can attach to either current compatibility fields or observation IDs.

Commands:

- `make test`
- `docker compose up postgres pgadmin backend frontend`
- `s env OPENAI_API_KEY LANGFUSE_PUBLIC_KEY LANGFUSE_SECRET_KEY LANGFUSE_BASE_URL -- make backend`
- `s env HF_TOKEN OPENAI_API_KEY LANGFUSE_PUBLIC_KEY LANGFUSE_SECRET_KEY LANGFUSE_BASE_URL -- docker compose up`

Manual end-to-end checks:

- Search a property once and verify cache miss + AI/SAM calls.
- Search the same property again and verify cache hit + no duplicate token spend.
- Force TTL stale and verify refresh.
- Confirm records appear in Postgres/pgAdmin.
- Confirm Langfuse trace/session contains cache status, prompt version, model usage, and no secrets.
- Confirm app still returns useful data if SAM service is down.
